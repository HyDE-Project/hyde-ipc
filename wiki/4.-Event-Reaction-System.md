# 4. Event-Reaction System

The core of `hyde-ipc`'s power lies in its event-reaction system. This system allows you to listen for specific Hyprland events and automatically execute one or more dispatcher commands in response.

This enables a level of automation and customization far beyond simple keybindings.

## Key Concepts

*   **Event**: An action that occurs within Hyprland, such as a window opening, the active workspace changing, or a monitor being connected.
*   **Reaction**: A user-defined rule that binds an **Event** to one or more **Dispatchers**.
*   **Dispatcher**: A command to be executed when the event occurs. This can be any command from the **[Dispatchers list](https://github.com/your-repo/hyde-ipc/wiki/3.-Dispatchers)**.
*   **Filter**: An optional condition that must be met for the reaction to trigger. Currently, filters are primarily used to match specific windows based on their properties (class, title, etc.).

## How It Works

The `hyde-ipc` process can listen to the Hyprland event socket. When an event arrives, the `ReactionManager` checks if any loaded reactions match the event type.

If a match is found, it then checks any associated filters. If all conditions are met, it executes the sequence of dispatchers defined in the reaction.

## Modes of Operation

There are two ways to define reactions:

### 1. Inline Mode

For simple, temporary, or test reactions, you can define a single reaction directly on the command line using the `react --inline` command.

This is useful for testing an idea without creating a configuration file.

**Example**:
Let's say you want to test a rule that automatically makes any Alacritty terminal float.

```bash
hyde-ipc react --inline \
  --event window --subtype active \
  --filter "class:^(Alacritty)$" \
  togglefloating
```
*   `--event window --subtype active`: We are watching for the `active` window event.
*   `--filter "class:^(Alacritty)$"`: The reaction only triggers if the active window's class matches the "Alacritty" regex.
*   `togglefloating`: This is the dispatcher that will be executed.

### 2. Config File Mode

For permanent and complex automation, the recommended approach is to use a TOML configuration file. This is the most powerful feature of `hyde-ipc`.

You can define dozens of reactions in a single, easy-to-read file. This file is typically loaded by the `systemd` service, making your automations persistent.

**Example `reactions.toml`**:
```toml
[[reactions]]
name = "Float Kitty Terminals"
event_type = { window = "active" }
window_filter = "class:^(kitty)$"
dispatchers = [
  { name = "togglefloating" }
]

[[reactions]]
name = "Chrome on Workspace 2"
event_type = { window = "opened" }
window_filter = "class:^(google-chrome)$"
dispatchers = [
  { name = "movetoworkspace", args = ["2"] }
]

[[reactions]]
name = "Screenshot Sound"
description = "Play a sound after taking a screenshot with grim"
event_type = { window = "closed" }
window_filter = "class:^(grim)$"
dispatchers = [
    { name = "exec", args = ["paplay", "/usr/share/sounds/freedesktop/stereo/camera-shutter.oga"] }
]
```

To learn the detailed syntax for this file, see the **[Configuration](https://github.com/your-repo/hyde-ipc/wiki/5.-Configuration)** page.

To load this configuration, you can either use the `react` command directly or install it for the background service with the `global` command.

```bash
# One-off execution with a config file
hyde-ipc react --config /path/to/your/reactions.toml

# Install the config for the background service
hyde-ipc global --config-path /path/to/your/reactions.toml
```
This system provides the building blocks for creating a highly personalized and automated window management experience in Hyprland.
