# 6. Practical Examples and Recipes

This page provides a collection of practical examples and recipes to showcase the capabilities of `hyde-ipc`. You can adapt these for your own workflows.

---

## 1. Quake-Style Dropdown Terminal

This recipe uses the event-reaction system to create a "Quake-style" terminal that appears at the top of the screen when you press a key and disappears when you press it again.

**How it works**:
We'll bind a key in `hyprland.conf` to run a script. This script will check if a special "dropdown" terminal is open. If not, it opens one. If it *is* open, it simply focuses it. `hyde-ipc` then handles the logic of moving the terminal out of view when it loses focus.

**Step 1: `hyprland.conf` Keybinding**
```ini
# hyprland.conf
bind = $mainMod, GRAVE, exec, ~/.config/hypr/scripts/dropdown_terminal.sh
```

**Step 2: The `dropdown_terminal.sh` script**
```bash
#!/bin/sh

# Check if the dropdown terminal is already open
if hyprctl clients | grep -q "class: dropdown-terminal"; then
    # If it exists, focus it
    hyde-ipc dispatch focuswindow "class:dropdown-terminal"
else
    # If it doesn't exist, create it
    kitty --class dropdown-terminal &
fi
```
*Make sure to `chmod +x ~/.config/hypr/scripts/dropdown_terminal.sh`.*

**Step 3: The `hyde-ipc` Reaction (`reactions.toml`)**
This is the core of the logic. We define two reactions.

```toml
# ~/.config/hyde-ipc/reactions.toml

[[reactions]]
name = "Dropdown Terminal: Position on Open"
description = "When the dropdown terminal opens, move it to the top and make it float."
event_type = { window = "opened" }
window_filter = "class:^(dropdown-terminal)$"
dispatchers = [
  { name = "movetoworkspace", args = ["special"] },
  { name = "togglefloating" },
  { name = "resizeactive", args = ["exact", "1920", "500"] },
  { name = "moveactive", args = ["exact", "0", "0"] }
]

[[reactions]]
name = "Dropdown Terminal: Hide on Focus Loss"
description = "When the dropdown terminal loses focus, move it back to the special workspace."
event_type = { window = "active" }
# This filter is tricky: it triggers when the *new* active window is NOT the dropdown.
# Hyprland doesn't have a "focus lost" event, so we react to the "active" event
# and check that the newly active window isn't our terminal.
# NOTE: This requires a more advanced filter not yet implemented.
# A simpler, effective alternative is to just toggle it with the same key.
# The script above handles the toggle logic. When you press the key again on the
# focused terminal, it will lose focus, and this second reaction is not needed
# if you use a script-based toggle.

# For a pure hyde-ipc solution, you would need a way to react to "focus lost",
# which can be simulated by reacting to "active" and checking the new window.
# The logic for that is more complex. The script-based toggle is often more reliable.
```
*This example highlights how `hyde-ipc` can be combined with simple shell scripts to achieve complex behavior.*

## 2. Centering Floating Windows

This reaction will automatically center any window the moment you toggle it into floating mode.

```toml
# reactions.toml

[[reactions]]
name = "Center on Float"
description = "When a window's float state changes, center it if it is now floating."
# This requires a "float" event and the ability to check the new state.
# Assuming a "float_state_changed" event exists in the library:
event_type = "float"
# We would need a way to get the window address from the event and check its state.
# If the library provides this, the dispatcher would be:
dispatchers = [
  # Hypothetical: { name = "centerwindow", args = ["address:{event.window_address}"] }
]
```
**Note**: The current implementation in `reaction_handler.rs` shows a generic `float` event. To make this recipe work perfectly, the event handler would need to provide the window address and its new floating state, and a way to filter on that state. A simpler approach is to just create a keybind that does both actions:
`bind = $mainMod, F, exec, hyde-ipc dispatch togglefloating && hyde-ipc dispatch centerwindow`

## 3. Sound Notifications for Events

Get auditory feedback for certain actions.

```toml
# reactions.toml

[[reactions]]
name = "Monitor Change Sound"
description = "Play a sound when the active monitor changes."
event_type = "monitor"
dispatchers = [
    { name = "exec", args = ["paplay", "/usr/share/sounds/freedesktop/stereo/device-added.oga"] }
]

[[reactions]]
name = "Workspace Change Sound"
description = "Play a sound when switching workspaces."
event_type = { workspace = "changed" }
dispatchers = [
    { name = "exec", args = ["paplay", "/usr/share/sounds/freedesktop/stereo/navigation-transition.oga"] }
]
```

## 4. Automatic Workspace Management

Automatically move applications to their designated workspaces when they open.

```toml
# reactions.toml

[[reactions]]
name = "Move Terminals to WS 1"
event_type = { window = "opened" }
window_filter = "class:^(kitty|Alacritty)$"
dispatchers = [
  { name = "movetoworkspacesilent", args = ["1"] }
]

[[reactions]]
name = "Move Browsers to WS 2"
event_type = { window = "opened" }
window_filter = "class:^(firefox|google-chrome)$"
dispatchers = [
  { name = "movetoworkspacesilent", args = ["2"] }
]

[[reactions]]
name = "Move Communication Apps to WS 9"
event_type = { window = "opened" }
window_filter = "class:^(discord|Slack)$"
dispatchers = [
  { name = "movetoworkspacesilent", args = ["9"] }
]
```
This keeps your desktop organized automatically. Using `movetoworkspacesilent` is key, as it moves the window without stealing your focus.
