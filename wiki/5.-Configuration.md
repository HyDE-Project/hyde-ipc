# 5. Configuration (`reactions.toml`)

The `hyde-ipc` event-reaction system is configured using a TOML file, typically named `reactions.toml`. This file contains an array of `[[reactions]]` tables, where each table defines a single, self-contained automation rule.

This page serves as a detailed reference for all the keys available within a `[[reactions]]` block.

## Default Location

When using the `setup` and `global` commands, `hyde-ipc` expects the configuration file to be at:
`~/.config/hyde-ipc/reactions.toml`

## Top-Level Structure

The configuration file is a list of reaction tables.

```toml
# reactions.toml

[[reactions]]
# ... first reaction definition ...

[[reactions]]
# ... second reaction definition ...
```

---

## Reaction Table Keys

Each `[[reactions]]` table can contain the following keys:

### `name` (Optional)
A string that gives your reaction a human-readable name. This is used for logging and makes debugging easier.

*   **Type**: String
*   **Example**: `name = "Float Kitty Terminals"`

### `description` (Optional)
A more detailed string describing what the reaction does.

*   **Type**: String
*   **Example**: `description = "Plays a sound after taking a screenshot with grim"`

### `event_type` (Required)
Defines the event that will trigger this reaction. It can be a simple string for events without subtypes, or a table for events with subtypes.

*   **Type**: String or Table
*   **Valid String Values**: `"monitor"`, `"float"`, `"fullscreen"`, `"layout"`, `"config"`
*   **Table Format**: `{ <type> = <subtype> }`
    *   **`window` subtypes**: `"opened"`, `"closed"`, `"moved"`, `"active"`
    *   **`workspace` subtypes**: `"changed"`, `"added"`, `"deleted"`
    *   **`group` subtypes**: `"toggled"`, `"moved-in"`, `"moved-out"`

*   **Examples**:
    ```toml
    event_type = { window = "opened" }
    event_type = { workspace = "changed" }
    event_type = "fullscreen"
    ```

### `window_filter` (Optional)
A string that filters window-related events. The reaction will only trigger if the window's properties match this filter. This is only applicable for `window` events.

*   **Type**: String
*   **Format**: Uses the same syntax as **[Window Identifiers](https://github.com/your-repo/hyde-ipc/wiki/3.-Dispatchers)** (`class:REGEX`, `title:REGEX`, etc.).
*   **Example**: `window_filter = "class:^(kitty|Alacritty)$"`

### `max_count` (Optional)
An integer that limits how many times this reaction can be triggered. Once the counter is reached, the reaction becomes disabled for the current session.

*   **Type**: Integer
*   **Default**: `0` (unlimited)
*   **Example**: `max_count = 1`

### `dispatchers` (Required)
An array of tables, where each table represents a dispatcher command to be executed when the reaction is triggered. The dispatchers are executed sequentially in the order they are defined.

*   **Type**: Array of Tables

Each dispatcher table has two keys:
*   `name` (Required): The name of the dispatcher (e.g., `exec`, `movetoworkspace`).
*   `args` (Optional): An array of string arguments for the dispatcher.

*   **Example**:
    ```toml
    dispatchers = [
      { name = "movetoworkspace", args = ["3"] },
      { name = "exec", args = ["notify-send", "Window Moved", "The window was moved to workspace 3."] }
    ]
    ```

## Complete Example

Here is a complete example of a `reactions.toml` file demonstrating various features:

```toml
[[reactions]]
name = "Float Specific Windows"
description = "Makes file manager and settings windows float when they become active."
event_type = { window = "active" }
window_filter = "class:^(thunar|pavucontrol)$"
dispatchers = [
  { name = "togglefloating" }
]

[[reactions]]
name = "Browser on Workspace 2"
description = "When a browser window opens, move it to workspace 2."
event_type = { window = "opened" }
window_filter = "class:^(firefox|google-chrome)$"
dispatchers = [
  { name = "movetoworkspace", args = ["2"] }
]
max_count = 10 # Limit to 10 times per session

[[reactions]]
name = "Notify on Config Reload"
description = "Send a desktop notification when the Hyprland config is reloaded."
event_type = "config"
dispatchers = [
    { name = "exec", args = ["notify-send", "Hyprland", "Configuration reloaded successfully."] }
]
```
