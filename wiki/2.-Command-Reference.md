# 2. Command Reference

This page provides a detailed reference for all `hyde-ipc` commands and their options, as defined in `flags.rs`.

---

## `dispatch`

Executes a Hyprland dispatcher command. This is one of the most frequently used commands for direct control of the compositor.

### Syntax
```bash
hyde-ipc dispatch [--async] [--list-dispatchers] [COMMAND]
```

### Options
*   `--async`, `-a`: Executes the dispatch command asynchronously without waiting for it to complete.
*   `--list-dispatchers`, `-l`: Prints a comprehensive list of all available dispatcher commands and exits.

### Subcommands
The `dispatch` command takes a single subcommand, which is the name of the dispatcher to execute (e.g., `exec`, `killactivewindow`).

For a complete list of dispatchers and their specific arguments, see the **[Dispatchers](https://github.com/your-repo/hyde-ipc/wiki/3.-Dispatchers)** page.

### Example
```bash
# Open a terminal
hyde-ipc dispatch exec "kitty"

# Move focus to the window on the right, asynchronously
hyde-ipc dispatch --async movefocus right
```

## `listen`

Connects to the Hyprland event socket and logs all incoming events to the console. This is primarily a tool for debugging, development, or discovering event names.

### Syntax
```bash
hyde-ipc listen [--filter <TYPE>] [--max-events <N>]
```

### Options
*   `--filter`, `-f <TYPE>`: Filters the output to only show events of a specific type (e.g., `window`, `workspace`, `monitor`).
*   `--max-events`, `-n <N>`: Exits automatically after `N` events have been received. If `0` (the default), it listens indefinitely.

### Example
```bash
# Listen for all events
hyde-ipc listen

# Listen for only workspace-related events, and stop after 5
hyde-ipc listen --filter workspace --max-events 5
```

## `react`

The entry point for the event-reaction system. It can be used for a simple, one-off reaction or to load a complex set of reactions from a configuration file.

### Syntax
```bash
# Inline mode
hyde-ipc react --inline --event <EVENT> [--subtype <SUBTYPE>] [--filter <FILTER>] --max-reactions <N> <DISPATCH_COMMAND>

# Config file mode
hyde-ipc react --config <PATH>
```

### Options
*   `--config`, `-c <PATH>`: Loads a TOML configuration file defining multiple reactions.
*   `--inline`, `-i`: Specifies that the reaction is defined directly on the command line.
*   `--event`, `-e <EVENT>`: The event type to react to (e.g., `window`, `workspace`). **Required for inline mode.**
*   `--subtype`, `-s <SUBTYPE>`: The event subtype for more specific filtering (e.g., `opened` for a `window` event).
*   `--filter`, `-f <FILTER>`: A window filter for window events (e.g., `"class:firefox"`).
*   `--max-reactions`, `-n <N>`: The maximum number of times the reaction should trigger. `0` for unlimited.
*   `<DISPATCH_COMMAND>`: The dispatcher command to execute when the event occurs. **Required for inline mode.**

### Example
```bash
# When a new window opens, move it to the next workspace
hyde-ipc react --inline -e window -s opened movetoworkspace right:1

# Load a full set of reactions from a config file
hyde-ipc react -c ~/.config/hyde-ipc/reactions.toml
```

## `keyword`

Gets or sets a Hyprland keyword value.

### Syntax
```bash
hyde-ipc keyword [--async] (--get | --set) <KEYWORD> [VALUE]
```

### Options
*   `--async`, `-a`: Performs the operation asynchronously.
*   `--get`, `-g`: Gets the value of the specified keyword.
*   `--set`, `-s`: Sets the value of the specified keyword. Requires a `VALUE`.
*   `<KEYWORD>`: The name of the keyword (e.g., `general:border_size`).
*   `[VALUE]`: The value to set for the keyword.

### Example
```bash
# Get the current border size
hyde-ipc keyword --get general:border_size

# Set the border size to 2
hyde-ipc keyword --set general:border_size 2
```

## `query`

Queries Hyprland for specific information.

### Syntax
```bash
hyde-ipc query <COMMAND>
```

### Subcommands
*   `cursor-pos [--watch]`: Gets the current cursor position.
    *   `--watch`, `-w`: Watches for changes and logs the position continuously.

### Example
```bash
# Get the current cursor x and y coordinates
hyde-ipc query cursor-pos
```

---

## `setup`

Manages the `systemd` user service for running `hyde-ipc` persistently.

### Syntax
```bash
hyde-ipc setup <COMMAND>
```

### Subcommands
*   `--install`: Installs the `systemd` user service.
*   `--uninstall`: Uninstalls the service.
*   `--start`: Starts the service.
*   `--kill`: Stops the service.
*   `--restart`: Restarts the service.
*   `--check`: Checks the status of the service.
*   `--watch`: Tails the service logs.

---

## `global`

Installs a global reaction configuration file and restarts the service. This is the primary way to configure the background service.

### Syntax
```bash
hyde-ipc global --config-path <PATH>
```

### Options
*   `--config-path`, `-c <PATH>`: The path to the configuration file to be installed. This file will be copied to the appropriate system location (e.g., `~/.config/hyde-ipc/reactions.toml`).

### Example
```bash
# Install a local config file for the service to use
hyde-ipc global -c ./my-reactions.toml
```
